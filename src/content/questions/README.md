# questions コレクション

1問 = 1ファイル（ファイル名はその日の日付 `YYYY-MM-DD.json`）。スキーマは `src/content.config.ts` で定義。

高市首相の在任期間（2025-10-21就任）の日付のみを対象とする。

日付はすべて実在の日付。歴代首相動静を構造化した公開データ（GitHub: isamu/sori、元データは
官邸ログ/kanteilog.com が時事通信・日本経済新聞・朝日新聞の動静を数値化したもの）の
「公務時間(work_min)」「居所滞在時間(residence_min)」「場所」「分類ごとの時間」といった
数値・事実のみを根拠にしている。個々の記事や分類ラベルの原文は引用せず、`text` は
すべてオリジナルで書き下ろした。

- `stay: true` … work_min=0 かつ居所が「公邸」だった日。`text` は定型句で統一（`終日、公邸で過ごす。`）
- `stay: false` … それ以外（work_min>0、または居所が公邸以外だった日）

isamu/sori は各首相の就任から1年間のみを収録しており、高市首相については2026-10-20までしかカバーしない。
それ以降（2026-11-01〜）の日付は、同じ数値・事実のみを根拠に kanteilog.com の該当日ページから直接参照しており、
ここでも記事や分類ラベルの原文は引用していない。

2026-11-01以降の日付は `scripts/update-daily-question.mjs` で自動生成できる（`.github/workflows/update-daily-question.yml`
が毎日実行し、前日分が未収録なら追加してpushする）。kanteilog.comのページに埋め込まれた構造化データ
（区間ごとのcategory/location/時刻）のみを事実として使い、サイト側の説明文（description）は使わない。
生成される文章は手作業で書いたものよりテンプレート的（カテゴリごとの定型句の組み合わせ）になる。
単調さを避けるため、ケース（短時間の外出／公邸に一部滞在／公邸に戻らず／終日ほかの場所）ごとに
同じ事実を述べる複数の言い回しを用意し、日付のハッシュで決定的に1つを選ぶ（同じ日付なら何度生成しても同じ文になる）。
言い回しの違いは表現のみで、構造化データにない情報は加えない。`stay: true` の定型句 `終日、公邸で過ごす。` は変えない。
